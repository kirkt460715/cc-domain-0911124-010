# 清账

核对企业应收、回款、贷项、争议和核销关系，提供单笔匹配建议、批次级全局核销、账龄快照与期间关闭。所有金额按币种最小单位保存，不合并不同币种余额。

演练创建合成发票和回款，确认核销，登记争议并关闭期间，随后验证历史快照与调整记录。批次演练（clearing-demo）构造交叉争抢、同分替代、部分回款、弱证据边、人工锁定与确认前余额变化，对比逐笔贪心与全局方案，并演示整批拒绝与失败留痕。

批次级核销（receivables/matching/clearing*.py）把同一客户、同一币种、同一业务截止下的多笔回款与开放发票做成只读快照统一求解：硬约束（同客户同币种、可用与开放余额、锁定项）由容量网络保证，再按证据收益、未分配金额与拆分成本的字典序比较方案；允许部分核销与保留未分配款，绝不跨客户或跨币种拼平。求解器是不触碰账本的纯函数（最小费用最大流 + 确定性集中后处理），结果不依赖输入顺序，平局给出稳定首选与同分替代并显式标注歧义。证据目标与权重可保存为带版本的配置；去掉任一候选边可量化目标变化，识别仅数值最优但无参考号/到期证据的弱证据边；人工锁定部分后可重算其余部分。确认在同一事务内逐项重验可用余额、争议登记与期间状态，任一处过时整批拒绝、不部分入账，重复确认幂等，失败原因另表留痕且原建议保持不变。

主要代码位于 receivables，按 books、matching、importers、reporting 划分职责；tests 保存领域行为、边界及存储回归用例。命令接收严格 JSON，详细操作名与字段可通过对应帮助入口及 service 中的注册表查询。示例中的机构、客户、案件和测量均为本地合成记录，不涉及真实个人资料。

使用 Python 3.11.2 与标准库，无第三方包。运行无需访问外部服务或提供账号。依赖清单 requirements.txt 为空，.python-version 固定解释器版本。

在项目根目录运行：

```sh
python3 -m unittest discover -s tests -v
python3 -m compileall -q receivables
python3 -m receivables demo
python3 -m receivables clearing-demo
```

也可执行下面的统一检查，按顺序进行语法编译、领域回归和完整本地演练，任一环节失败即退出。运行写入均在临时目录或内存数据库，重复执行不需清理已有业务账。正常数据规模的检查可在 90 秒内完成。

```sh
sh scripts/check.sh
```
